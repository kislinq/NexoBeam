# NexoBeam Messenger

Next-generation realtime Android messenger with cyber-luminescent aesthetic and Supabase backend.

## 🚀 Настройка Supabase Backend

1. **Создайте проект в [Supabase](https://supabase.com)**
2. **Выполните SQL Migration:**
   * Откройте **SQL Editor** в консоли Supabase.
   * Скопируйте и выполните содержимое файла `supabase/migrations/20260926_init_nexobeam.sql`.
   * Затем выполните `supabase/migrations/20260927_fix_membership_rls.sql`. Он исправляет рекурсивные RLS-политики, из-за которых не удаётся создавать чаты и отправлять сообщения.
   * Если проект Supabase уже настроен, достаточно выполнить только новую миграцию `20260927_fix_membership_rls.sql`.
   * Это создаст все таблицы (`profiles`, `chats`, `chat_members`, `messages`, `attachments`, `user_devices`), триггеры, индексы и политики Row Level Security (RLS).
3. **Настройте Storage Buckets:**
   * Перейдите в **Storage** в Supabase.
   * Создайте бакет `avatars` с публичным доступом (`Public Bucket = true`). Миграция `20260927_fix_membership_rls.sql` добавляет права загрузки только в личную папку пользователя.
   * Создайте бакет `chat-attachments` с приватным доступом (`Public Bucket = false`).
4. **Скопируйте ключи проекта:**
   * В **Project Settings > API** скопируйте:
     * `Project URL`
     * `anon / public key`
   * Добавьте их в файл `.env` в корне проекта или в Secrets панель AI Studio:
     ```env
     SUPABASE_URL=https://your-project.supabase.co
     SUPABASE_ANON_KEY=eyJhbGciOi...your-anon-key
     ```

## Подключение через Render

В каталоге `proxy/render` находится HTTPS reverse proxy для Auth, REST, Storage и Realtime WebSocket. Он пересылает запросы только на заданный Supabase URL и не использует service-role key. Доступ к данным по-прежнему контролируется RLS. Для развёртывания:

1. Поместите проект в GitHub/GitLab-репозиторий, если он ещё не опубликован в Git-хостинге.
2. В Render выберите **New > Blueprint** и подключите этот репозиторий. Render обнаружит корневой `render.yaml`.
3. При создании сервиса задайте `SUPABASE_URL` как переменную окружения из Project URL Supabase.
4. После deploy скопируйте HTTPS URL сервиса Render.
5. В приложении откройте **Сервер и доступность**, укажите этот URL, проверьте соединение и сохраните. Если восстановление сессии зависло на стартовом экране, через 5 секунд появится кнопка **«Проблемы со входом? Настроить сервер»**. После закрытия настроек приложение повторит восстановление сессии уже через сохранённый адрес.

### Уменьшение cold start на Render Free

В Render можно настроить внешний периодический запрос к `/_health`: входящие HTTP-запросы сбрасывают 15-минутный idle-таймер. В репозитории добавлен workflow `.github/workflows/render-keepalive.yml` с запросами на 2, 16, 30, 44 и 58 минут каждого часа: обычно интервалы 14 минут, а между 58-й минутой и 2-й следующего часа — 4 минуты.

#### Публикация Render-прокси и включение пингов

1. Запушьте весь проект в GitHub-репозиторий вместе с корневым `render.yaml` и папкой `proxy/render`.
2. На [render.com](https://render.com) нажмите **New → Blueprint**, выберите этот GitHub-репозиторий и подтвердите создание сервиса `nexobeam-supabase-proxy` на плане **Free**.
3. Когда Render запросит `SUPABASE_URL`, вставьте **Project URL Supabase** вида `https://<project-ref>.supabase.co`. Это адрес upstream-сервера для прокси, не URL Render и не API key. Не добавляйте к нему `/rest/v1` или другой путь.
4. Дождитесь успешного deploy. Скопируйте **URL сервиса Render** вида `https://<service-name>.onrender.com` и проверьте в браузере `https://<service-name>.onrender.com/_health` — ответ должен быть `ok`.
5. Чтобы GitHub Actions мог будить прокси, откройте GitHub-репозиторий: **Settings → Secrets and variables → Actions → Variables → New repository variable**. Имя: `RENDER_PROXY_URL`, значение: базовый URL Render без `/_health`.
6. Убедитесь, что workflow лежит в default branch. Откройте **Actions → Keep Render proxy awake → Run workflow** и запустите его вручную. В логе ожидается ответ `ok`; последующие запуски идут по расписанию.
7. В приложении откройте **Сервер и доступность**, вставьте базовый URL Render, проверьте соединение и сохраните. Адрес Render надо задавать именно приложению; значение `SUPABASE_URL` в настройках Render остаётся адресом Supabase.

Расписание GitHub Actions не гарантирует точное время: запуски могут задерживаться или пропускаться при высокой нагрузке GitHub; расписания работают только для workflow в default branch. Поэтому единичный пропущенный запуск может дать cold start. Для публичного репозитория GitHub-hosted минуты бесплатны; в приватном репозитории регулярные запуски расходуют Actions minutes по лимитам аккаунта. Если workflow упал, откройте его лог в **Actions** и проверьте наличие repository variable `RENDER_PROXY_URL`.

Render Free выделяет общий пул **750 часов на workspace за календарный месяц**. Запросы keep-alive не обходят этот лимит: один постоянно работающий сервис расходует 720 часов за 30-дневный месяц или 744 часа за 31-дневный месяц. В 31-дневном месяце остаётся только около 6 часов на остальные Free-сервисы workspace. Если лимит исчерпан, Render приостанавливает Free-сервисы до сброса месячного лимита. План workspace Hobby сам по себе не снимает ограничения Free compute plan. Следите за временем и bandwidth в Render Dashboard.

Официальное описание ограничений: [Render Free instances](https://render.com/docs/free).

### Примерная оценка bandwidth

Render считает исходящий трафик сервиса, а прокси пересылает данные и между телефоном и самим Supabase. Для каждого файла примерно учитываются его байты при загрузке через прокси в Supabase и при каждой последующей отдаче получателю. Поэтому оценка для одного отправителя и одного получателя — около `2 × размер файла`; на каждого дополнительного просмотревшего добавляется ещё примерно `1 × размер файла`. Например, при среднем фото 0,5 МБ на лимит 5 ГБ приходится ориентировочно до 5 000 пар «одна загрузка + одно скачивание», без учёта протокольных накладных расходов, повторных скачиваний и остальных ответов прокси. Файл 20 МБ видео даст около 40 МБ на одного получателя; 100 таких пересылок — около 4 ГБ. Сжимайте медиа и следите за фактическим usage в Render.

Сейчас элементы вложений в приложении не являются полноценной доставкой файлов: отправка сообщения сохраняет текст, но не загружает вложение в Storage; кнопки голосового сообщения и документа используют демонстрационные URI. Не рассчитывайте bandwidth как на готовую файловую функцию, пока отдельно не реализованы загрузка, сохранение `attachments`, выдача URL, скачивание и воспроизведение.

## 🎨 Темы оформления (3 концепции)
Приложение поддерживает моментальное переключение между тремя уникальными визуальными стилями:
1. **Industrial Tech-Monochrome (По умолчанию):** Строгий аэрокосмический кибер-терминал с контрастным Cyber-Lime / Laser акцентом и геометричными бабблами.
2. **Luminescent Cyber-Minimalism:** Глубокий обсидиановый фон со световыми импульсами («Beam») Cyan $\to$ Electric Blue и неоновыми нимбами.
3. **Spatial Neo-Glass:** Кристальная полупрозрачность, ультра-мягкие суперэллипсы и лавандово-мятные акценты.
